⚡ InitAutomatic - Tek Adımda Hazırlık

Önerilen yöntem: Backend'de oluşturulan session bilgileri otomatik olarak SDK'ya taşınır.

🏢 Backend İşlemleri:

Merchant backend şunları yapar:

  • Masterpass session oluşturur
  • Temp token oluşturur
  • Token içine session bilgilerini ekler
1 PaywallJsSdk.InitAutomatic() SDK + Session Bilgileri
2 PaywallJsSdk.providers.masterpass.init() Provider
3 Account/Card Operations accountAccess, merchantLink, addCard, deleteCard
4 Payment Operations init, registerAndPurchase, verifyOtp

✅ Avantajlar:

  • Backend'den gelen session bilgileri otomatik parse edilir
  • Tek SDK çağrısı ile tüm bilgiler hazır
  • SessionId, userId, userPhone otomatik alınır
  • Daha az kod, daha az hata riski

💻 Kod Örneği:

{{ codeExampleAutomatic }}

🔧 InitManual - Manuel Adımlar

Eski yöntem: Session bilgileri SDK'ya otomatik taşınmaz, manuel olarak yönetilir.

🏢 Backend İşlemleri (Manuel):

Merchant backend şunları yapar:

  • Masterpass session oluşturur
  • Session bilgilerini ayrı tutar (token içinde değil)
  • SessionId'yi merchant tarafında saklar
1 PaywallJsSdk.InitManual() Sadece SDK Init
2 SDK.startSession() KALDIRILDI - Backend'de yapılmalı
3 PaywallJsSdk.providers.masterpass.init() Provider
4 Account/Card/Payment Operations SessionId manuel geçilmeli

⚠️ Dezavantajlar:

  • SDK'nın startSession() metodu kaldırıldı
  • Session bilgileri backend'den manuel alınmalı
  • SessionId her API çağrısında manuel geçilmeli
  • Daha fazla manuel işlem, daha fazla hata riski

💻 Eski Kod (Artık Önerilmiyor):

{{ codeExampleManual }}
⚠️ Uyarı: SDK'nın startSession() metodu kaldırıldı. Session artık merchant backend tarafında oluşturulmalı. InitAutomatic kullanarak session bilgilerini otomatik alabilirsiniz!

🎯 Önerimiz

Yeni projeler için InitAutomatic kullanmanızı öneriyoruz. Daha hızlı, daha güvenli ve daha az hata ile entegrasyon sağlar.
